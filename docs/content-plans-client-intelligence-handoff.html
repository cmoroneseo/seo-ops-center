1. Product outcome

North-star outcome A strategist can turn client context and SEO opportunities into an approved, prioritized content roadmap, then promote individual opportunities into real tasks or deliverables without re-entering the planning data.

Planning layer

Organize work as Content Plans → Topic Clusters → Content Opportunities.

Execution bridge

Approved opportunities can become existing SEO PM Tool tasks and deliverables.

Global and client-scoped entry points

  • /content shows the all-client Content Plans portfolio.
  • The client workspace Content Plan tab shows the same planning system pre-filtered to one client.
  • The client workspace Client Intelligence tab owns the reusable client profile.
  • The plan header includes a contextual profile indicator: readiness, last updated date, profile version, and a Review link.

4. Primary user flows

A. Create a plan

  1. Select client.
  2. Name the plan and optional planning period.
  3. Review inherited Client Intelligence.
  4. Add seed topics, services, locations, or source keywords.
  5. Generate or manually create clusters and opportunities.
  6. Review before saving generated ideas.

B. Review opportunities

  1. Filter by cluster, intent, opportunity type, priority, and status.
  2. Assign an optional primary target page to the cluster.
  3. Approve, reject, edit, or move opportunities.
  4. Flag duplicates, cannibalization risks, and existing-page refreshes.

C. Promote to execution

  1. Select an approved opportunity.
  2. Create a Task or Deliverable using existing creation logic.
  3. Carry across title, keyword, intent, target page, notes, due date, and assignment.
  4. Retain the source link for traceability.

D. Maintain client context

  1. Edit structured Client Intelligence fields.
  2. Validate AI-suggested values before saving.
  3. Publish a new profile version.
  4. Explicitly regenerate plan suggestions using the latest context.

6. Client Intelligence specification

Client Intelligence should improve business relevance during planning. It is not a full visual asset manager or content-generation settings panel in the MVP.

SectionMVP fieldsUsed during planning
BusinessName, website, description, business model, primary conversion, differentiators, proof pointsScores business fit and opportunity type.
OffersProducts/services, priority offerings, high-margin offerings, exclusionsPrevents irrelevant recommendations and prioritizes commercial value.
AudiencesSegments, buyer roles, needs, objections, funnel stageShapes cluster framing and recommended intent.
MarketsLocations, service areas, language, national/local scopeDetermines location-page and localized-content opportunities.
SEO contextCompetitors, priority themes, existing target pages, target conversion pathsInforms coverage gaps and primary target-page selection.
Brand & compliancePreferred terminology, prohibited claims, regulated topics, tone summaryConstrains suggestions and titles.

Database conventions

  • Add a numbered migration and mirror it into schema.sql.
  • Apply tenant RLS using organization_id IN (SELECT get_user_org_ids()).
  • Index client, plan, cluster, status, task, and deliverable foreign keys used in filters.
  • Use snake_case database fields and rowToX/xToRow mappers in the Supabase layer.
  • Compute plan rollups on read; do not persist selected, approved, promoted, or published totals.

9. AI generation behavior

  • AI output is a proposal requiring review, not an automatic write into the active plan.
  • Generation uses structured Client Intelligence, plan settings, supplied seeds, and known existing URLs.
  • Every generated opportunity includes a short rationale, suggested type, intent, cluster, and target-page relationship.
  • The prompt explicitly prohibits inventing services, locations, credentials, pricing, guarantees, or claims.
  • The saved plan records the Client Intelligence version used for generation.
  • Profile changes do not silently rewrite existing opportunities.
  • Regeneration with current context is an explicit user action.
MVP recommendation Use structured fields in the prompt. Do not build embeddings, document retrieval, or a generalized knowledge graph until the planning workflow proves valuable.

10. UX and accessibility requirements

  • Icon-only primary navigation links have accessible names and visible keyboard focus.
  • Active navigation state is communicated by text/semantics as well as color.
  • Tabs use correct tab semantics or are implemented as URL links when they navigate.
  • Tables remain operable at 200% zoom and provide a usable responsive alternative.
  • Bulk actions announce selection count and remain keyboard accessible.
  • Status, intent, and priority chips do not communicate meaning by color alone.
  • Inline edits have explicit labels, Save/Cancel behavior, validation, and error recovery.
  • AI loading, completion, and failure states are announced and do not trap focus.
  • Destructive archive, reject, unlink, or delete actions require appropriate confirmation.
  • Mobile navigation exposes Content and the client-scoped Content Plan/Intelligence destinations.

11. MVP acceptance criteria

  • Content appears in primary desktop and mobile navigation and opens the Content Plans library.
  • No empty or one-item secondary Content navigation rail is introduced.
  • Users can create, rename, open, activate, and archive a client-scoped Content Plan.
  • Users can create, edit, reorder, and remove Topic Clusters.
  • Users can create, edit, filter, approve, reject, and bulk-update Content Opportunities.
  • Clusters support an optional primary target page; it is not required or always called a pillar page.
  • Users can classify opportunities as landing pages, articles, refreshes, FAQs, location pages, comparisons, consolidation, or no action.
  • Users can promote an approved opportunity to a Task or Deliverable and navigate to the linked record.
  • Client Intelligence is editable in the client workspace and not present under Personal Tools.
  • The plan shows which Client Intelligence version informed generated recommendations.
  • Plan metrics are computed from current opportunities and linked execution records.
  • All new tables have organization-scoped RLS and authorization is tested across tenants.
  • Typecheck, lint, relevant unit tests, and a production build pass before handoff.
